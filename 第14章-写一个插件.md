# 第 14 章 写一个插件（Cookbook）

## 14.1 插件的基本结构

一个 dsh 插件就是一个导出一个函数或 Service 类的模块。最基本的插件：

```typescript
// packages/my-plugin/src/index.ts
import { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.logger('my-plugin').info('Plugin loaded')
}
```

Cordis 加载器读取这个包时，会调用 `apply(ctx)`。`inject` 数组告诉加载器：在调用 `apply` 之前，确保 `ctx.tools` 可用。

本章按功能逐步构建一个完整的插件。

## 14.2 注册一个工具

```typescript
// packages/my-plugin/src/index.ts
import { Context } from '@deepseek-ai/cordis'

export const name = 'my-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register({
    name: 'hello',
    description: 'Say hello to someone',
    parameters: {
      type: 'object',
      properties: {
        name: { type: 'string', description: 'The name to greet' },
      },
      required: ['name'],
    },
    output: {
      schema: { type: 'string' },
      render: (args, value) => [{ type: 'text', text: value as string }],
    },
    execute: async (args, exec) => {
      return `Hello, ${args.name}!`
    },
  })
}
```

这个工具注册后，模型就能调用 `hello` 工具。参数通过 JSON Schema 验证，返回值通过 `output.render` 转为模型可见的 content。

## 14.3 在工具管线中监听事件

```typescript
// packages/my-plugin/src/logging-plugin.ts
export const name = 'logging-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  const log = ctx.logger('tools')

  // 记录所有工具调用意图
  ctx.on('tools/pre-execute', (exec, next) => {
    log.info(`Tool ${exec.name} called with args: ${JSON.stringify(exec.args)}`)
    return next() // 必须调用 next() 让管线继续
  })

  // 记录所有工具执行结果
  ctx.on('tools/result', (exec, result) => {
    log.info(`Tool ${exec.name} completed with status: ${result.isError ? 'error' : 'success'}`)
  })
}
```

注意 `tools/pre-execute` 是 waterfall——如果不调用 `next()`，管线会在当前的监听器处停下，后续监听器不会执行。

## 14.4 注册一个拦截策略

```typescript
// packages/my-plugin/src/safety-plugin.ts
export const name = 'safety-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  // 拒绝所有在 deny list 中的工具
  ctx.tools.registerGuard((execution) => {
    const denied = ['delete_everything', 'rm_rf']
    if (denied.includes(execution.name)) {
      return 'this tool is not allowed by safety policy'
    }
    return undefined // 放行
  })
}
```

守卫的返回值 `undefined` 表示放行，非 `undefined` 字符串为拒绝原因。守卫不会被"批准"逻辑覆盖——它是单调的。

## 14.5 注册一个 Prompt Section

```typescript
// packages/my-plugin/src/prompt-plugin.ts
export const name = 'prompt-plugin'
export const inject = ['systemPrompt']

export function apply(ctx: Context) {
  // 注册一个带变量的动态 section
  ctx.systemPrompt.variable('my_var', () => 'dynamic value')

  ctx.systemPrompt.section({
    name: 'my-plugin:instructions',
    order: 150,
    text: `You should always follow these instructions: {{my_var}}`,
  })
}
```

## 14.6 监听 Agent 生命周期

```typescript
// packages/my-plugin/src/lifecycle-plugin.ts
export const name = 'lifecycle-plugin'
export const inject = ['agents']

export function apply(ctx: Context) {
  // 在每个 agent 创建时附加自定义行为
  ctx.on('agent/created', ({ agent }) => {
    ctx.logger('lifecycle').info(`Agent ${agent.id} created`)

    // 在 agent 的 scoped context 中注册工具
    agent.ctx.tools.register({
      name: `agent_specific_tool`,
      // ...
      execute: async (args, exec) => { /* ... */ },
    })
  })
}
```

`agent.ctx` 是 scoped context。在其上注册的工具只对该 agent 可见。`agent/created` 事件支持 scope-filtered dispatch，所以监听器收到的 `{ agent }` 已经是确定 scope 的。

## 14.7 注册一个 Runtime Context 注入

```typescript
// packages/my-plugin/src/context-plugin.ts
export const name = 'context-plugin'
export const inject = ['systemPrompt']

export function apply(ctx: Context) {
  ctx.systemPrompt.context({
    name: 'my-plugin:custom-context',
    order: 100,
    text: () => {
      const data = fetchSomeRuntimeData()
      return `Current custom context: ${JSON.stringify(data)}`
    },
  })
}
```

每个 step 都会重新求值 `text` 函数。上下文作为 user/message 前缀插入消息历史，而非 system prompt 的一部分。

## 14.8 自定义 Service

如果插件需要维护自己的状态和绑定，可以声明为一个 Service：

```typescript
// packages/my-counter/src/index.ts
import { Context, Service } from '@deepseek-ai/cordis'

declare module '@deepseek-ai/cordis' {
  interface Context {
    counter: CounterService
  }
}

interface Config {
  initialValue?: number
}

export class CounterService extends Service {
  static Config = { initialValue: { type: 'number', default: 0 } }

  private count: number

  constructor(ctx: Context, config: Config) {
    super(ctx, 'counter')
    this.count = config.initialValue ?? 0
  }

  increment(): number {
    return ++this.count
  }

  get value(): number {
    return this.count
  }
}

export default CounterService
```

其他插件通过 `inject: ['counter']` 声明依赖，然后使用 `ctx.counter.increment()`。Service 的实例化和销毁由 Cordis 自动管理。

## 14.9 自定义 Compaction Engine

替换默认的压缩引擎：

```typescript
// packages/my-compaction/src/index.ts
import { CompactionEngine, type CompactionResult } from '@deepseek-ai/dsh-compaction'

export class MyCompactionEngine extends CompactionEngine {
  async compact(events, surface) {
    // 自定义压缩逻辑
    return { /* CompactionResult */ }
  }
}

export function apply(ctx: Context) {
  ctx.compaction.register(new MyCompactionEngine())
}
```

## 14.10 配置声明

插件可以在 `Config` 中声明可配置项：

```typescript
export interface Config {
  enabled?: boolean
  threshold?: number
}

export function apply(ctx: Context, config: Config) {
  if (config.enabled === false) return

  const threshold = config.threshold ?? 100

  // 使用配置项...
}
```

Config 的 schema 通过 `z.object()` 定义（schemastery）。YAML 加载器会验证 config 的类型和默认值。配置可以通过 settings UI 热更新，触发 `settings/updated` 事件。
